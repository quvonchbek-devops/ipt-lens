# IPT-Lens v0.1.0 Open-Source Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the private IPT-Lens prototype into a publishable MIT-licensed project with the known safety bugs fixed, English everywhere, tests, CI and community docs.

**Architecture:** Unchanged: one Go binary, `internal/iptables` (parse, simulate, validate, watchdog), `internal/api` (HTTP + auth), `internal/enricher`, embedded static UI in `web/dist`. Changes are fixes inside those packages plus packaging and docs around them.

**Tech Stack:** Go 1.21+ (stdlib only), vanilla JS/CSS UI, GitHub Actions, GoReleaser, systemd.

**Spec:** Assessment in the session of 2026-10-28 (Stage 1 of the roadmap), approved by the maintainer: "Stage 1, MIT, English, fix everything that needs improvement, work with plan, changelog and the other md files".

## Global Constraints

- Module path: `github.com/quvonchbek-devops/ipt-lens`.
- License: MIT, copyright `2026 Quvonchbek Nuriddinov`.
- Language: all user-facing strings, error messages, code comments and docs in English.
- No new third-party Go dependencies (stdlib only).
- Minimum Go version stays `go 1.21` in `go.mod`.
- The API surface (`/api/v1/*` paths and JSON field names) stays backward compatible; new fields may be added.
- Version string: `0.1.0`, injected via `-ldflags "-X main.version=..."`, default `dev`.

## Review Focus

1. Process crash between "rule applied" and "pending recorded": the change must still be rolled back on next start (Task 2 test `TestBeginWritesPendingBeforeApply`).
2. A forward command fails halfway: nothing may stay applied and no pending state may remain (Task 2 test `TestBeginForwardFailureCleansUp`).
3. A browser page on another origin POSTs to a token-less loopback instance: must be refused (Task 6 tests `TestPostRequiresJSON`, `TestCrossSiteRejected`, `TestHostHeaderRejected`).
4. A rule with match modules the simulator cannot evaluate (`-m set`, `-m limit`, `--src-range`): the verdict must be flagged uncertain, never silently presented as exact (Task 4 test `TestSimulateFlagsUnsupportedMatch`).
5. Comments containing escaped quotes (`--comment "say \"hi\""`) as printed by `iptables-save`: must round-trip through parse and undo (Task 5 test `TestTokenizeEscapedQuotes`).

### Task 2: Crash-safe watchdog

**Files:** Modify `internal/iptables/watchdog.go`; Test `internal/iptables/watchdog_test.go`

**Interfaces:**
- Produces: `NewWatchdog(dir string, demo bool, timeout time.Duration, opts ...Option) (*Watchdog, error)`; `type Option func(*Watchdog)`.

- [ ] Tests (stub `runIPT`/`runSave` via a recording fake):
  - `TestBeginWritesPendingBeforeApply`: in the fake, when the forward command runs, `pending.json` already exists and contains the undo.
  - `TestBeginForwardFailureCleansUp`: two forward commands, second fails → undo of the first ran, `pending.json` absent, `Status()` = not pending, error returned.
  - `TestExpireRunsUndo`: timeout 10ms → undo command recorded, pending cleared.
  - `TestConfirmClearsPending`, `TestRecoverOnStart`: a `pending.json` present at `NewWatchdog` → undo runs, file removed.
- [ ] Implement: `begin` writes pending (with undo for the full plan) before forward; on forward failure, run the undo for the commands already executed (in reverse), remove pending, return the error.
- [ ] Commit `fix(watchdog): record pending change before applying it`.
